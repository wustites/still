# Still

A local-first video and image player for Windows, built with Flutter.

Still indexes folders you choose, shows a single library for video and images,
plays video through libmpv, and keeps playback progress on disk. No accounts, no
network services, no telemetry.

## Status

Early skeleton (`0.1.0`). The library, player, image viewer, settings and
persistence layers are implemented; platform folders are generated by the
bootstrap scripts.

## Features

- Add any number of folders; scans run in a background isolate.
- One grid for videos and images, with search, sort and favourites.
- Resume playback, recent list, play counts.
- media_kit / libmpv playback: hardware decoding, audio and subtitle tracks,
  external subtitles, speed control, screenshots.
- Custom desktop controls (auto-hide, keyboard shortcuts, native fullscreen).
- Image viewer with pan/zoom, rotation, fit modes and an EXIF panel.
- Drift + SQLite storage; playback state survives rescans and unplugged drives.
- Optional ffmpeg-based video poster frames; styled placeholders without it.

## Requirements

- Flutter `3.50.1` (Dart `3.14`).
- Windows 10/11 for the primary target. Linux and macOS runners can be generated
  too, but are untested.
- Optional: `ffmpeg` on `PATH` for video thumbnails.

## Getting started

The repository intentionally does not commit the `windows/`, `linux/` or
`macos/` runner folders: Flutter generates them per host, and they contain
machine-specific build files.

On Windows:

```powershell
powershell -ExecutionPolicy Bypass -File tool\bootstrap.ps1
flutter run -d windows --release
```

On Linux/macOS:

```bash
./tool/bootstrap.sh
flutter run -d linux   # or macos
```

`bootstrap` runs `flutter create` in a temporary folder, copies the platform
runners in, then runs `flutter pub get` and the Drift code generator.

Without the bootstrap step `lib/data/db/app_database.g.dart` does not exist and
the app will not compile.

## Verification

CI (`.github/workflows/verify.yml`) is the source of truth:

- `ubuntu-latest`: `pub get` → Drift codegen → `flutter analyze` → tests.
- `windows-latest`: generate the Windows runner → codegen → debug build.

CI can prove compilation, analysis and tests. It **cannot** validate GPU
behaviour; hardware decoding, 4K playback and HiDPI rendering need a real
Windows machine. Do not try to run an x86_64 Flutter SDK on an ARM64 host via
qemu/binfmt: Flutter does not publish a Linux ARM64 SDK, and a malformed
binfmt_misc rule can break `execve` for the whole machine.

### Windows checklist

- [ ] H.264 / HEVC / AV1 files play with `hwdec=auto` (check Task Manager GPU
      video-decode usage).
- [ ] 4K60 playback stays smooth with controls visible; no dropped frames in
      mpv logs.
- [ ] ASS subtitles render with the requested font size and stay above the
      control bar; SRT and external files load.
- [ ] Audio track switching and subtitle switching work without restarting.
- [ ] Window resize, maximise and fullscreen keep the correct aspect ratio.
- [ ] At 150% and 200% display scaling, text and controls are crisp and the
      library grid reflows correctly.
- [ ] Resume position is written every 5 seconds and on pause/close.

## Architecture

```
lib/
  data/
    db/            Drift database, tables, generated schema
    models/        media kind, filters, scanner DTOs
    repositories/  library + settings persistence
  services/
    scan/          isolate directory scan, scan lifecycle
    thumbnails/    ffmpeg poster frames
    media/         EXIF reader
  features/
    library/       sidebar, toolbar, grid, tiles
    player/        media_kit controller, custom controls
    viewer/        image viewer, EXIF panel
    settings/      preferences
  ui/              theme and shared widgets
  app.dart         provider wiring
  main.dart        bootstrap
```

**Threading.** Directory walks and thumbnail decoding never run on the UI
isolate. Playback state arrives through media_kit streams; only high-frequency
positions use a `ValueNotifier` so the video surface does not rebuild 10×/s.

**Data.** SQLite is the only source of truth. `media_items.path` is unique and
holds playback state; a rescan upserts metadata and marks unseen rows `missing`
instead of deleting them. Foreign keys cascade from library roots.

## Keyboard shortcuts

Player: `Space`/`K` play-pause, `←`/`→` seek 10s, `↑`/`↓` volume, `M` mute,
`F` fullscreen, `S` subtitles, `Esc` back.

Viewer: `←`/`→` previous/next, `+`/`-` zoom, `0` reset, `R` rotate, `I` info,
`F` immersive mode, `Esc` back.

## Known limitations

- Playlist tables exist; the playlist UI is not built yet.
- No filesystem watcher yet; rescans are manual or on folder add.
- Video thumbnails require ffmpeg; without it the grid uses placeholders.
- Only Windows is validated. Linux/macOS may need packaging work.
